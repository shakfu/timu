## Executive Summary

**timu** (Swahili for *team*) is a specialized multi-agent coding framework written in modern Python. Its guiding philosophy is to coordinate role-scoped, capability-constrained LLM agents toward concrete software engineering objectives while maintaining **zero runtime dependencies** and enforcing **OS-level isolation**.

Unlike typical monolithic or conversational agent frameworks (e.g., CrewAI, AutoGen, ChatDev) that rely primarily on prompt instructions to restrict behavior and dump entire conversational histories into a shared context window, `timu` treats agent roles as **immutable data**, confines execution using **OS sandboxes** (`sandbox-exec` on macOS and `bubblewrap` on Linux), tracks data provenance to eliminate the **"Lethal Trifecta"** of prompt injection, and isolates agent communication through **typed hand-offs** (`Task`, `Result`, `Artifact`).

## 1. Domain Landscape & Value Proposition

### 1.1 The Problem Space

Autonomous software engineering with Large Language Models has rapidly evolved across three distinct generations:

1. **Interactive Conversational Assistants (e.g., Aider, Claude Code, GitHub Copilot Chat):** Single-agent loops interacting directly with the developer in an interactive terminal or IDE. Fast and flexible, but susceptible to context rot and prone to accidental workspace pollution.

2. **Heavyweight Autonomous Benchmarking Agents (e.g., SWE-agent, OpenHands):** Designed primarily for SWE-bench benchmarks. Often packaged inside heavy Docker containers with complex Python dependencies, running long-horizon planning with variable reproducibility.

3. **Multi-Agent Conversational Frameworks (e.g., CrewAI, AutoGen, MetaGPT):** Agents interacting via free-form text in a shared chat room. These frameworks suffer from context bloat ("telephone game" degradation), prompt injection vulnerabilities, lack of deterministic execution, and reliance on model compliance rather than OS-level security.

### 1.2 Where `timu` Fits

`timu` carves out a distinct and valuable niche at the intersection of **lightweight developer tooling** and **rigorous capability security**:

- **Zero Runtime Dependencies:** Built entirely on Python 3.11+ standard library modules ([`tomllib`](file:///Users/sa/projects/personal/timu/src/timu/config.py), [`urllib`](file:///Users/sa/projects/personal/timu/src/timu/tools/web.py), [`graphlib.TopologicalSorter`](file:///Users/sa/projects/personal/timu/src/timu/graph.py), [`subprocess`](file:///Users/sa/projects/personal/timu/src/timu/tools/shell.py), [`dataclasses`](file:///Users/sa/projects/personal/timu/src/timu/types.py)).

- **True OS Capability Enforcement:** When a role lacks a capability (e.g., network access or file writes), it is blocked by kernel/OS-level primitives (`sandbox-exec` / `bwrap`) and path-resolving decorators, not merely by asking the LLM not to run those commands.

- **Taint-Aware Provenance:** Defends against the *Lethal Trifecta* (untrusted web input + access to private data + capability to exfiltrate or write). Web data is marked `Origin.NET` and quarantined in random-delimited wrappers (`<untrusted-HEX>`).

- **Clean Hand-Offs over Shared Context:** Sub-agents receive only the goal and designated artifacts. Conversations do not cross agent boundaries, drastically reducing token spend and context degradation.

- **Local Clone Isolation:** Avoids modifying the user's working checkout in-place. Work is conducted in disposable local clones (`~/.local/state/timu/work/`), verified against post-review tampering, and committed cleanly to an isolated branch for the user to fetch.

## 2. Assessment of Usefulness

### 2.1 Core Strengths & Key Use Cases

1. **Autonomous "Fix & Review" Loops (`fix-review`, `review-validate-fix`):**
   - In [`src/timu/workflow.py`](file:///Users/sa/projects/personal/timu/src/timu/workflow.py), workflows pair a `coder` (read/write/exec, offline) with independent verification roles (`reviewer`, `validator`, `verifier`).

   - The reviewer runs tests in a read-only sandbox where workspace writes are forbidden. Its report must yield an explicit verdict (`VERDICT: APPROVE` or `VERDICT: CHANGES`). A bounded loop (`--review-to-fix N`) provides self-correction without runaway token burn.

2. **Safe Web Research Integration (`research-fix-review`):**
   - The `researcher` role has `Capability.NET` but zero filesystem tools (`read_roots=()`, [`src/timu/roles.py`](file:///Users/sa/projects/personal/timu/src/timu/roles.py#L69-L76)). It can search and fetch documentation, but cannot touch the workspace or read private repository files.

   - Any fetched web content passes to the coder as tainted, untrusted data. With `--approve-untrusted`, human approval is mandated before untrusted data is consumed by roles with execution capabilities.

3. **Multi-Repository Orchestration via DAGs (`timu graph run`):**
   - [`src/timu/graph.py`](file:///Users/sa/projects/personal/timu/src/timu/graph.py) elevates multi-agent workflows across repositories. Directed acyclic graphs run workflows in topological order, passing structured outputs (`toml:FILE#KEY`, `changelog:latest`, `git:diff`, `file:GLOB`) between nodes.

   - Independent nodes execute concurrently in thread pools (`--max-parallel N`), with synchronized console logging and serialized approval prompts.

   - Graph runs support resumption (`--resume RUN`), re-evaluating only invalidated nodes based on git commit hashes.

4. **Extensible Python API for UI and Tool Embedding:**
   - [`src/timu/api.py`](file:///Users/sa/projects/personal/timu/src/timu/api.py) exposes the full capabilities of `timu` programmatically.

   - Includes thread-safe event streaming (`sink`), cancellation tokens (`cancel`), and interactive approval brokers (`Approvals`) designed to interface seamlessly with graphical user interfaces, background workers, or web services.

5. **Operational Economy & Budget Ceilings:**
   - Enforces multi-dimensional budgets (turns, tool calls, token usage, cost in USD, wall-clock time) at both agent and workflow levels ([`src/timu/types.py`](file:///Users/sa/projects/personal/timu/src/timu/types.py)).

   - Native awareness of prompt caching (Anthropic ephemeral cache and OpenAI prompt tokens details), allowing accurate tracking of cache reads and cache creation writes.

### 2.2 Practical Limitations & Operational Boundaries

1. **The Dependency Installation Paradox:**
   - Because the `coder` role is sandboxed without network access (`Capability.NET`), commands such as `pip install`, `uv add`, or `npm install` fail inside coder turns.

   - *Workaround / Mitigation:* The host environment must be pre-provisioned, or a distinct unconfined installation role must be used. In practical workflows, if an agent needs to add a dependency to solve an issue, it can edit `pyproject.toml`, but cannot run the resolver/installer itself.

2. **Git Clone Model Ergonomics:**
   - By defaulting to `git clone --local`, `timu` starts strictly from `HEAD`. Uncommitted modifications, stashes, and untracked files (such as `.env` or local test fixtures) are omitted.

   - The user must explicitly fetch the resulting branch (`git fetch <copy> <branch>:<branch>`). While this ensures total safety for the host checkout, developers seeking rapid in-place interactive pairing must use `--in-place`, which re-opens potential attack surfaces from nested git configurations.

3. **Platform-Specific Sandboxing Variance:**
   - **macOS (`sandbox-exec`):** While `MacSandbox` ([`src/timu/sandbox.py`](file:///Users/sa/projects/personal/timu/src/timu/sandbox.py#L60-L75)) effectively isolates the filesystem, the underlying Apple Seatbelt facility is deprecated, starts from `(allow default)`, and cannot block `KERN_PROCARGS2` inspections (allowing a sandboxed process to view environment variables of peer user processes).

   - **Linux (`bubblewrap`):** Relies on unprivileged user namespaces. Modern distributions (e.g., Ubuntu 23.10+ / 24.04+) restrict unprivileged namespaces via AppArmor by default, requiring administrative intervention ([`docs/dev/bwrap.md`](file:///Users/sa/projects/personal/timu/docs/dev/bwrap.md)).

4. **Task Scope & Refactoring Scale:**
   - `timu` excels at targeted, verifiable tasks: fixing a failing unit test, applying a security patch, or upgrading an API.

   - For open-ended, architectural refactorings spanning hundreds of files, single-turn context limits and string-replacement editing ([`src/timu/tools/fs.py:edit`](file:///Users/sa/projects/personal/timu/src/timu/tools/fs.py)) require extensive turn counts that approach budget boundaries.

### 3.2 Security Engineering & Prompt Injection Defenses

`timu` stands out as one of the most security-conscious agent harnesses currently published. Its defenses tackle the most critical failure modes identified by modern AI security research:

1. **Segregation of the Lethal Trifecta:**
   - Simon Willison’s *Lethal Trifecta* occurs when an agent simultaneously possesses: (1) access to untrusted inputs, (2) access to private data, and (3) an outbound communication channel.

   - `timu` enforces at startup that **no single role may hold `Capability.NET` together with `Capability.FS_WRITE` or `Capability.EXEC`** ([`src/timu/role.py:validate`](file:///Users/sa/projects/personal/timu/src/timu/role.py#L25-L35)).

2. **Tainted Data Tracking & Cryptographic Framing:**
   - Any artifact originating from or derived from web interactions carries `Origin.NET` and `untrusted=True` ([`src/timu/types.py`](file:///Users/sa/projects/personal/timu/src/timu/types.py)).

   - When injected into a downstream agent's prompt, it is enclosed in `<untrusted-[nonce]>` tags with a per-task cryptographically random hex suffix ([`src/timu/agent.py:render_task`](file:///Users/sa/projects/personal/timu/src/timu/agent.py#L380-L395)). Untrusted text cannot prematurely close a tag whose nonce it cannot predict.

3. **Host OS Hardening & Git Defense:**
   - **Environment Sanitization:** Parent secrets (such as API keys) are scrubbed from execution environments ([`src/timu/tools/shell.py:scrubbed_env`](file:///Users/sa/projects/personal/timu/src/timu/tools/shell.py#L61-L76)); `HOME` points to an isolated temporary scratch directory.

   - **Git Hook & Persistence Protection:** Sandboxed commands cannot create or write to `.git` outside scratch directories. Host git drivers, diff filters, and hooks are forcefully blanked ([`src/timu/graph.py:_git`](file:///Users/sa/projects/personal/timu/src/timu/graph.py#L860)) to prevent prompt-injected repository config attacks.

   - **Bare Repository Defense:** Commits fail if an agent crafts an embedded bare repository layout designed to trigger execution on subsequent user git status calls ([`src/timu/graph.py:seal`](file:///Users/sa/projects/personal/timu/src/timu/graph.py#L425-L450)).

   - **Post-Review Snapshot Verification:** A workspace tree hash is recorded prior to review; any late writes by detached agent background processes invalidate the commit seal.

4. **Network & SSRF Guardrails:**
   - `web_fetch` ([`src/timu/tools/web.py`](file:///Users/sa/projects/personal/timu/src/timu/tools/web.py)) verifies IP addresses via `socket.getaddrinfo` prior to connection, explicitly refusing private, link-local, loopback, or multicast addresses to block cloud metadata service access (e.g., `169.254.169.254`) and internal microservices.

### 3.3 Context Window Management & LLM Operational Practices

1. **Proactive & Reactive Context Management:**
   - Rather than allowing conversation buffers to grow monotonically, `timu` implements proactive trimming ([`src/timu/agent.py:maybe_trim`](file:///Users/sa/projects/personal/timu/src/timu/agent.py#L270-L315)): when replies exceed 64,000 input tokens, tool outputs older than the last 3 turns are stubbed (`STUB = "[trimmed by timu:..."`).

   - High-cost results (such as `delegate` and `load_skill`) are explicitly exempt from trimming.

   - On a 400 Context Overflow error, `timu` aggressively truncates all but the immediate previous turn and transparently retries.

2. **Prompt Cache Accounting:**
   - Reflects the latest 2025/2026 provider pricing dynamics: prompt caching significantly alters agent economics.

   - Supports Anthropic and OpenAI prompt caching details (`cached_input_tokens`, `cache_write_input_tokens`) in [`src/timu/types.py:Usage`](file:///Users/sa/projects/personal/timu/src/timu/types.py#L18-L45) and [`src/timu/config.py:Price`](file:///Users/sa/projects/personal/timu/src/timu/config.py).

3. **Graceful Tool Interfaces:**
   - Tools return structured values (`ToolOutput(is_error=True)`) rather than raising unhandled exceptions ([`src/timu/tools/fs.py:_guard`](file:///Users/sa/projects/personal/timu/src/timu/tools/fs.py#L63-L75)). The model receives clear diagnostic text, enabling autonomous error correction without crashing the agent loop.

4. **Resilient Streaming & Retries:**
   - In [`src/timu/cli.py`](file:///Users/sa/projects/personal/timu/src/timu/cli.py), if an API provider stream fails mid-generation (e.g., OpenRouter 502/503), the CLI marks the restart point on the console and retries without corrupting the conversation history with partial messages.

### 3.4 Software Engineering & Testing Rigor

1. **Zero External Dependencies:**
   - Tested and verified via [`tests/test_package.py::test_has_no_runtime_dependencies`](file:///Users/sa/projects/personal/timu/tests/test_package.py). Eliminates supply chain risks, dependency conflicts, and deployment friction.

2. **Type Safety & Static Analysis:**
   - Configured with `mypy.strict = true`. Every function signature is typed, with zero type errors across the entire codebase.

3. **Simulation & Empirical Ground Truth (`scripts/sim.py`):**
   - Moves beyond flaky "LLM-as-a-judge" evaluations.

   - Includes 9 seeded tasks (`calc`, `lru`, `slugify`, `duration`, `stats`, `control`, and 3 regression tasks from real `timu` patches).

   - Measures pass rates with hidden oracle tests run inside sandboxes, computing 95% bootstrap confidence intervals, false accept rates, and cost per solved task.

## 4. Gap Analysis & Key Recommendations

While `timu` is exceptionally well-engineered, the following enhancements would elevate its real-world effectiveness and adoption:

### R1. Containerized / Micro-VM Sandboxing (`sanduk` Integration)

- **Context:** macOS `sandbox-exec` is deprecated and carries known kernel information leak vectors (`KERN_PROCARGS2`). Linux `bubblewrap` requires unprivileged user namespace capabilities, which are blocked on default modern distributions like Ubuntu 24.04.

- **Recommendation:** Implement the containerized sandbox abstraction outlined in design section 15.8 (`sanduk`). Running roles inside lightweight, disposable OCI containers or micro-VMs (e.g., Apple Virtualization framework on macOS, crun/Podman on Linux) would provide cross-platform consistency and bulletproof namespace isolation.

### R2. Resolve the Dependency Installation Constraint

- **Context:** The coder role's lack of network access prevents updating lockfiles or installing third-party packages needed to fix bugs.

- **Recommendation:** Introduce a specialized, tightly scoped `installer` role or pre-flight phase. An installer could receive a declared manifest diff (e.g., changes to `pyproject.toml` or `package.json`), run the package manager with network access in an isolated container without access to private repository files or credentials, and return the updated lockfile and environment.

### R3. First-Party Provider Packages

- **Context:** Core currently implements an OpenAI-compatible HTTP streaming client via `urllib`. The entry-point plugin mechanism (`timu.providers`) is defined, but no official packages exist for native Anthropic, Google Gemini, or AWS Bedrock APIs.

- **Recommendation:** Publish reference provider packages (e.g., `timu-anthropic`, `timu-gemini`) that implement `ProviderFactory` and native SDK features (thinking budgets, fine-grained cache controls, function calling nuances).

### R4. Interactive CLI Diff and Merge Experience

- **Context:** Currently, `timu run` outputs a `git fetch` command pointing to the local clone branch. The user must manually inspect and merge the changes.

- **Recommendation:** Provide an interactive CLI review mode upon run completion (e.g., `timu apply` or `timu diff`), allowing developers to review colored unified diffs, inspect test verdicts, and merge the branch into their working tree with a single keystroke.

### R5. Semantic Indexing for Large Codebases

- **Context:** The `search` tool runs regex matching over files using a subprocess worker. For large multi-thousand-file codebases, regex-only discovery can consume significant time and token budget.

- **Recommendation:** Add an optional, zero-dependency symbol indexing capability (leveraging Python's built-in `ast` module or ctags/etags) to allow agents to perform fast symbol definition and reference lookups without requiring heavy external vector databases.

## 5. Conclusion

**timu** is an outstanding example of disciplined, security-first AI systems engineering. It rejects the prevailing industry trend of building brittle, bloated agent frameworks layered atop complex dependency stacks. Instead, it demonstrates that a high-assurance, production-grade multi-agent system can be achieved using pure standard library Python, mathematically sound capability security, and rigorous software verification.

Its adoption of agentic best practices—role segregation, context isolation, prompt caching economics, typed hand-offs, and empirical simulation—places it at the forefront of robust autonomous coding architectures. Addressing containerized isolation and dependency installation ergonomics will make it an indispensable standard for automated repository maintenance and secure multi-agent collaboration.
